# Готовність MOTORNA до бети — 06.11.2026

Документ фіксує результати перевірок, без оцінки готовності у відсотках. Публічна технічна версія вже доступна; це не підтвердження готовності комерційного маркетплейсу.

## Перевірено автоматично
| Критерій | Доказ | Межі |
|---|---|---|
| Типи та production build | Typecheck/build у CI | Не доводить uptime зовнішнього сервісу |
| Основний користувацький шлях | 14 Playwright тестів desktop/mobile | Зовнішні VIN/магазин/фото дані контрольовані; auth/records/TXT справжні локальні |
| Доступ до чужих записів | access-security.mjs | Маршрути зі SQLite у пам’яті та A/B ідентичностями; не аудит провайдера авторизації |
| QR і приватні чеки | car-catalog.mjs, access-security.mjs | Після відкликання новий запит за старим URL повертає 404; вже завантажену копію відкликати неможливо |
| Документи | document-upload.mjs | Тип за сигнатурою та ліміт реального потоку; не антивірус і не повна перевірка формату |
| Сумісність та заявки | purchase-journey.mjs, API/E2E | Збіг артикула не є VIN-підтвердженням; заявка — чернетка, ручне передавання |
| Стан D1/R2 | /api/health | Read probe із TTL 15 с; 200/503, без деталей БД/користувача |

## Що ще не завершено
- Strict ESLint перевірено: 0 помилок, без baseline; попередження залишаються.
- Зовнішній моніторинг із каналом сповіщень і накопиченою історією доступності не налаштований. Health endpoint сам не надсилає повідомлень.
- Production backup/restore D1 і R2 не перевірено: немає окремого доступу до експорту/відновлення сховищ у цьому робочому середовищі. Наявність збережених версій коду не є резервною копією користувацьких даних.
- Хмарний snapshot МВС не оновлюється автоматично. Перед контрольованим імпортом потрібні перевірка джерела/дати/кількості записів, тестовий VIN, контроль відсутності даних власників, збереження попереднього snapshot та поетапне перемикання. Імпортний endpoint закритий без секрету; секрети не розміщують у Git.
- Повна юридична політика приватності з реквізитами оператора/контактом і строками зберігання не затверджена. Не вигадувати ці дані. Окремий процес видалення всіх даних Motorna ще не реалізований; видалення окремих записів не дорівнює видаленню облікового запису.
- Антивірус/PDF sanitization, розподілений rate limiting і незалежний security review не проведені.
- 5–10 реальних водіїв ще не пройшли формальне приймальне тестування; результати не підміняються автоматичними тестами.
- OEM-підтвердження, партнерський прийом заявки та підтверджені календарі СТО не підключені. Для бети заявка передається власником вручну.

Точкова production-перевірка: `npm run test:production` — сторінки, D1/R2 read probe, 401 для приватних API й діагностичний маршрут. Тривала історія доступності не збирається.

## Приймальне тестування з водіями
Перевірити на телефоні: VIN/підтвердження/гараж; пошук артикула та порожній результат; різницю артикула й сумісності; збереження/експорт чернетки; приватний чек; QR із дозволеним чеком і відкликання. Для кожного проходження записати дату, браузер, сценарій, фактичний результат і дефект. Не додавати реальні VIN/чеки людей у публічні issues без їх згоди.

Якщо нова публікація порушує основний сценарій: зафіксувати помилку без персональних даних, повторно розгорнути попередню збережену версію через Sites, перевірити `/api/health`, вхід, гараж і читання приватного документа. Перед першим відновленням D1/R2 потрібен окремий staging rehearsal із зашифрованою резервною копією, перевіркою кількості записів/власників/зв’язків документів/контрольних сум та повторним тестом відкликання QR. До виконання не позначати backup/restore як перевірений.

Оновлення 05.11: головний пошук має явні режими VIN / Запчастина / Симптоми. До вибору авто невідомі кузов/колір не показуються. Запит позначено як такий, що очікує ручного надсилання; кнопка веде до продавця, без автоматичної передачі. Новий інтерфейс передає Idempotency-Key: атомарний INSERT із конфліктом primary key не створює повторний запис. Сервер повертає перший VIN-знімок; той самий ключ з іншим вмістом повертає 409. Старі клієнти без ключа залишаються сумісними й не отримують цього захисту. Після явного видалення чернетки ключ не резервується назавжди.

GET records: серверні фільтри kind/carId/id/from/to, курсорна пагінація з межею 100 записів, стабільний порядок created/id та індекси з міграції 0001. UI завантажує старіші записи на вимогу; експорт проходить усі сторінки окремо від початкового завантаження. Контракти API, cursor scope, EXPLAIN і повний CSV на частковому списку перевіряються тестами.
