# Перевірки MOTORNA

## Команди та поточний стан

Перевірене середовище — Node.js 24; мінімум із package.json — >=22.13.0.

| Команда | Призначення |
|---|---|
| `npm run lint:strict` | `eslint .`; 07.11.2026: 0 помилок, 65 попередження, exit code 0 |
| `npm run lint` | Точний синонім lint:strict |
| `npm run typecheck` | TypeScript без генерації файлів |
| `npm test` | 32 регресійні набори без зовнішніх мережевих залежностей |
| `npm run build` | Production build через Vinext |
| `npm run test:e2e` | 11 сценаріїв × desktop/mobile = 22 тести |
| `npm run test:api` | Інтеграційний сценарій проти запущеного локального сервера |
| `npm run test:production` | Точкова перевірка опублікованого сайту без збереження даних |

ESLint не використовує baseline чи `--max-warnings=0`: warnings видно, але вони не спричиняють ненульовий exit code. Залишаються невикористаний код, залежності hooks, img та навігація. У eslint.config.mjs винятки обмежені сторонніми components/ui та hooks/use-mobile.ts; правила застосунку не послаблено.

## Чистий клон та CI

```sh
npm ci
node scripts/prepare-ci.mjs
npm run lint:strict
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`.github/workflows/ci.yml` запускає ці етапи на Windows/Node.js 24 і потім локальний API-сценарій. `prepare-ci.mjs` створює лише відсутній ігнорований маніфест локальних DB/BUCKET, без production-ідентичності. Production-секрети не потрібні. CI не публікує сайт; його конфігурація не доводить, що останній віддалений запуск пройшов.

## Регресії

Джерело переліку — scripts/test-regression.mjs. 32 набори охоплюють VIN і збагачення даних, точні артикули та сумісність, фільтри, запити на купівлю, ТО, діалог симптомів, маршрути СТО, QR/документи, авторизацію власника, health, типи та API-контракти, цілісність записів, пагінацію й клієнтський експорт, Origin/CSRF, потокові ліміти JSON і помилки API.

- access-security.mjs виконує реальні функції маршрутів зі SQLite у пам’яті та тестовим файловим сховищем. Підмінена лише серверна ідентичність A/B/анонім. Перевіряє власника, документи, QR opt-in/відкликання, idempotency та відсутність запису після відмови.
- record-integrity.mjs перевіряє конкурентні INSERT/DELETE, батьківські авто й заборону осиротілих записів.
- records-pagination.mjs перевіряє межу 1–100, стабільний created/id, фільтри, власника й курсор, EXPLAIN QUERY PLAN без TEMP B-TREE для чотирьох індексів. record-client.mjs перевіряє повний експорт і відмову при збої/зацикленні сторінок.
- document-upload.mjs перевіряє сигнатури та реальний потік понад ліміт із неправдивим Content-Length. Це не антивірус чи повна перевірка PDF/зображень.
- mutation-security.mjs перевіряє Origin, Fetch Metadata, недовірені Forwarded/Host, формати тіла, production/local і окрему політику машинного імпорту.
- json-body.mjs перевіряє UTF-8 байти, чанки, раннє скасування, відсутній/неправдивий Content-Length, malformed JSON/UTF-8 та обриви. Усі 12 JSON-читань використовують спільний ліміт.
- api-errors.mjs контролює всі 32 обробники, code/message/requestId, кореляцію заголовка/журналу, незалежні паралельні ID, безпечний 500 і незмінність успішних/файлових відповідей.

Ці перевірки не є незалежним security review, аудитом провайдера авторизації чи підтвердженням OEM-сумісності.

## Playwright E2E

Конфігурація — playwright.config.ts. Профілі: desktop 1440×1000 та mobile 375×812. Кожен із одинадцяти сценаріїв запускається в обох профілях:

1. API-помилки 400/403/404/413 мають спільний формат та X-Request-Id.
2. Підтверджений VIN відновлюється після входу.
3. Глобальні команди артикула/симптомів зберігають вибране авто.
4. Справжні браузерні JSON/multipart працюють; відхилені PATCH/DELETE не змінюють записи.
5. VIN → авто → артикул → фільтр → кількість → приватний запит → reload → TXT. Повтор після втраченої відповіді створює лише одну чернетку; demo не додається.
6. HTTP 503 джерела показує повідомлення нового формату та дозволяє запит без вигаданої ціни.
7. Перемикання авто очищає попередній QR-каталог у стані інтерфейсу.
8. Початковий екран приховує невідомі характеристики та розділяє режими пошуку.
9. Перша сторінка містить 50 із 61 витрати, CSV — усі 61; «Завантажити ще» додає решту, старіше авто залишається вибраним.

10. Наявні витрати, історія й запит одночасно блокують видалення авто (409); після послідовного очищення — 200, повтор — 404, старий QR і записи з видаленим carId недоступні.
11. Вісім конкурентних повторів із тим самим ключем створюють один запит; змінений payload — 409. Великі POST/PATCH і погані Origin зберігають початковий знімок. Шість DELETE успішні рівно один раз; повтор після видалення авто не відновлює запис.

Зовнішні VIN/фото/магазини — контрольовані фікстури. Для ізоляції QR-стану також підмінена відповідь QR-API. Auth/records/валідація власника/TXT та файловий тест працюють через справжній локальний сервер і сховище. Тести не доводять реальну ціну, доступність продавця чи OEM-сумісність. Власні тестові записи очищаються; production-облікові записи й секрети не використовуються.

Playwright запускає й завершує сервер; локальний уже запущений сервер можна повторно використати, у CI — ні. Лише localhost, без умовних E2E-обходів прав доступу в застосунку. Фіксованих sleep немає. playwright-report/ містить HTML-звіт; test-results/ — вибрані знімки успіху, знімки та traces помилок. Вони ігноруються Git; Actions зберігає звіт 7 днів.

## Локальний API-сценарій

Запустіть `npm run dev -- --host 127.0.0.1`, потім `npm run test:api`. Перевіряються збережений VIN, діагностика, приватний запит, повторне читання, TXT, анонімний доступ, чужий carId та demo-товари. Видаляються лише записи тесту. Запуск проти віддаленого домену заборонений самим тестом.

## Production smoke

`npm run test:production` читає публічні сторінки та health, перевіряє 401 приватних API і виконує діагностичні запити без збереження. Перевіряє Origin/CSRF, 413/400 для JSON та code/message/requestId із відповідним заголовком. Записи, файли й QR не створюються. Зовнішні відповіді не підміняються; збій спричиняє помилку. Успіх характеризує момент запуску, не історію uptime. Цей тест не входить до офлайн-регресій.

## Грошова міграція

money-migration.mjs перевіряє фінансову міграцію окремим офлайн-набором. Підготовку, покриття й обмеження нативної D1-репетиції описано в [MONEY_MIGRATION.md](MONEY_MIGRATION.md). Нативний money-d1.mjs запускається окремо; в поточному середовищі Workers runtime не стартує, тому успіх D1 не заявляється.

## Розширені перевірки безпеки операцій

record-integrity.mjs перевіряє всі три залежності одночасно, повний незмінений snapshot при 409 та повторні/конкурентні DELETE. access-security.mjs порівнює всі чотири таблиці й байти R2-об’єктів після відмов; JSON рівно 60 000 UTF-8 байтів приймається, перевищення JSON/multipart без Content-Length або з неправдивим значенням зупиняє читання. Матриця 13 наборів заголовків перевіряє POST/PATCH/DELETE записів, QR POST і документи POST/DELETE; POST-відмова Origin не читає тіло. Повторні відкликання QR/видалення документа не зачіпають інші дані.

Нові HTTP-сценарії містяться в tests/e2e/record-safety.spec.ts, обидва виконуються у desktop/mobile. Загалом лишається 32 офлайн-набори; розширено наявні набори, браузерних тестів тепер 28. Production-записи для цих тестів не використовуються.

Архітектурний набір `tests/architecture.mjs`: прийняття наявного VIN-кешу міграцією, монотонні migration timestamps, спільні DTO, D1 lease, кеш/TTL, фонова актуалізація та гонки із видаленням/зміною VIN/видаленням профілю. Purchase E2E проходить через HTTP 202 → повторний запит → пропозиції. Всього 32 офлайн-набори та 28 браузерних тестів; зовнішні відповіді у Playwright контрольовані.
