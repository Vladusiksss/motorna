## Що ще не завершено
- Лінтинг проходить, але залишається борг із 65 попереджень (невикористаний код, hooks, img і навігація). Це не помилки ESLint; strict-команда наразі не застосовує --max-warnings=0.
- Додано scheduled GitHub workflow із health/privacy probes, звітами й Telegram failure/recovery alerts. Канал @blgrv_vlad потребує TELEGRAM_BOT_TOKEN і числового TELEGRAM_CHAT_ID у GitHub Secrets; сповіщення вимкнено за вказівкою власника, подальше налаштування відкладено. Див. MONITORING.md.
- Production backup/restore D1 і R2 відкладено за вказівкою власника в цій ітерації; не перевірено: немає окремого доступу до експорту/відновлення сховищ у цьому робочому середовищі. Наявність збережених версій коду не є резервною копією користувацьких даних.
- Хмарний snapshot МВС не оновлюється автоматично. Перед контрольованим імпортом потрібні перевірка джерела/дати/кількості записів, тестовий VIN, контроль відсутності даних власників, збереження попереднього snapshot та поетапне перемикання. Імпортний endpoint закритий без секрету; секрети не розміщують у Git.
- Повна юридична політика приватності з реквізитами оператора/контактом і строками зберігання не затверджена. Не вигадувати ці дані. Реалізовано окремий процес видалення даних Motorna, write barrier та повторюване очищення R2. Залишається мінімальна технічна відмітка ID; нові записи цього профілю блокуються. Межі та залишкові orphan-файли описано у DATA_LIFECYCLE.md.
- Антивірус/PDF sanitization і незалежний security review не проведені. Розподілений D1 rate limiting додано; це не заміна WAF/DDoS-захисту.
- 5–10 реальних водіїв ще не пройшли формальне приймальне тестування; результати не підміняються автоматичними тестами.
- OEM-підтвердження, партнерський прийом заявки та підтверджені календарі СТО не підключені. Для бети заявка передається власником вручну.

Точкова production-перевірка: `npm run test:production` — сторінки, D1/R2 read probe, 401 для приватних API й діагностичний маршрут, Origin/CSRF, JSON-ліміти та формат помилок із requestId. Моніторинг зберігає контрольні звіти як GitHub artifacts 14 днів після запуску workflow; це не гарантія uptime.

Перед першим відновленням D1/R2 потрібен окремий staging rehearsal із зашифрованою резервною копією, перевіркою кількості записів/власників/зв’язків документів/контрольних сум та повторним тестом відкликання QR. До виконання не позначати backup/restore як перевірений.

Оновлення 05.11: головний пошук має явні режими VIN / Запчастина / Симптоми. До вибору авто невідомі кузов/колір не показуються. Запит позначено як такий, що очікує ручного надсилання; кнопка веде до продавця, без автоматичної передачі. Новий інтерфейс передає Idempotency-Key: атомарний INSERT із конфліктом primary key не створює повторний запис. Сервер повертає перший VIN-знімок; той самий ключ з іншим вмістом повертає 409. Старі клієнти без ключа залишаються сумісними й не отримують цього захисту. Після явного видалення чернетки ключ не резервується назавжди.

GET records: серверні фільтри kind/carId/id/from/to, курсорна пагінація з межею 100 записів, стабільний порядок created/id та індекси з міграції 0001. UI завантажує старіші записи на вимогу; експорт проходить усі сторінки окремо від початкового завантаження. Контракти API, cursor scope, EXPLAIN і повний CSV на частковому списку перевіряються тестами.

Money-v2 підготовлено, але не активовано. Перехід API/UI/export і нативна D1-репетиція залишаються передумовами застосування. [MONEY_MIGRATION.md](MONEY_MIGRATION.md) містить перевірений SQLite-сценарій та зафіксований збій запуску Workers runtime; production-дані не змінено.


## Перевірка поточної ітерації
- Міграція 0003 додає перевірки зв'язків документів/QR, write barrier для видаленого профілю та індекси. Runtime CREATE для цих таблиць усунено. Перевірено повторне застосування на SQLite. Наявні legacy-orphans не видаляються міграцією.
- data-lifecycle.mjs перевіряє RESTRICT для чека, QR revocation, безпечні повтори, збій R2, 33 файли, ізоляцію власників, auth/CSRF і body limits. Контрольовані SQL/R2 fixtures; реальні користувацькі дані не видалялися.
- Production env revision 2: додаткових provider secrets/flags немає. Комерційні фото-адаптери без ключів вимкнені; публічний keyless web search та Commons мають власні правила/TTL. EXACT_VIN_MATCH і MODEL_MATCH розділені; це не OEM-сумісність. Остання фактична зовнішня перевірка повернула 0 фото/status unavailable; позитивний production-збіг фото не підтверджено.
- Віддалений D1/R2 staging backup/restore залишається **не виконаним**: доступні інструменти Sites дають читання огляду/таблиць, не експорт і відновлення R2. Потрібен операторський доступ до окремого staging D1/R2 та захищеного сховища backup. Локальні SQLite-тести не видаються за цю перевірку.
- Money-v2 не активовано; попередня підготовлена міграція не запускається автоматично. Дати записів перевіряються як дійсні YYYY-MM-DD, URL пропозицій — HTTPS і seller allowlist. Повний перехід API/UI/export на minor units залишається окремим незавершеним етапом після backup/restore.
