# Сповіщення Motorna в Telegram

**Сповіщення вимкнено за вказівкою власника від 07.11.2026.** Workflow збирає лише технічні результати; Telegram не викликається, поки repository variable `MOTORNA_TELEGRAM_ALERTS_ENABLED` не має точного значення `true`. Токенів недостатньо для увімкнення.

Майбутній одержувач, обраний власником: `@blgrv_vlad`. Username особистого профілю не замінює числовий `chat_id` Bot API.

1. Створіть свого бота через офіційного [BotFather](https://t.me/BotFather) і відкрийте приватний діалог із ботом зі свого профілю; надішліть `/start`.
2. Отримайте `message.chat.id` через Bot API `getUpdates` у власному захищеному середовищі. Якщо бот уже використовує webhook, не змінюйте його для цієї перевірки: використайте отриманий ним update. Не вставляйте токен у загальнодоступні URL, issues, код або чат.
3. У GitHub → Vladusiksss/motorna → Settings → Secrets and variables → Actions додайте `TELEGRAM_BOT_TOKEN` та `TELEGRAM_CHAT_ID`. Друга змінна — додатне числове значення вашого приватного діалогу, не `@username`.
4. Коли вирішите ввімкнути повідомлення, додайте repository variable `MOTORNA_TELEGRAM_ALERTS_ENABLED=true`.
5. Actions → Motorna production monitoring → Run workflow. Без секретів звіт явно показує `not_configured`; це не підтвердження доставки. Перший успішний запуск не надсилає зайвого повідомлення. Для перевірки доставки використайте окреме тестове повідомлення з власного захищеного середовища.

Workflow перевіряє `/api/health` (D1/R2) та заборону анонімного доступу до records/documents; кожна перевірка має 15-секундний timeout і одну повторну спробу. Звіт не містить VIN, чеків, тіл приватних відповідей або секретів. Telegram отримує лише назви контрольних маршрутів і посилання на сайт. Повторний незмінний стан не сповіщає; після збою надходить повідомлення про відновлення. Невдале надсилання залишає старий стан для повторної спроби.

Розклад — приблизно кожні 15 хвилин. GitHub може затримувати scheduled runs і вимикати їх у неактивних публічних репозиторіях; це не SLA. Кеш стану може бути витіснений: тоді можливе повторне повідомлення про збій. Якщо сам GitHub Actions недоступний, цей канал не спрацює. Звіти зберігаються як artifacts 14 днів. `tests/production-smoke.mjs` дає ширшу ручну read-only перевірку API, CSRF і лімітів JSON.

Офіційна документація: https://core.telegram.org/bots/api#sendmessage

Статус на 07.11.2026: код і контрольовані тести готові; Telegram вимкнено. Налаштування секретів і перевірку доставки відкладено власником.
